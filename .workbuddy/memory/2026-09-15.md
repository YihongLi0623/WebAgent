## Train / Eval 是否必须启动全部网站（重要结论）

## 截图机制（第五轮，查清四个来源）
目录名是 `screehshots`（**少一个 n 的拼写错误**），run.py:445-448 创建并在每个任务开始时清空。
1. **主截图** `result_dir/screehshots/{task_id}/{i}.png`，`run.py:485-488`。`i = len(actions)` = 0-based step 序号。**在 `env.step(action)` 之前拍**（run.py:508 才 step），所以是"动作决定那一刻"的页面状态。每次两张调用：先 `env.page.screenshot(path="/dev/null")` 预热/强制重绘（**Windows 上会因 /dev/null 不存在而报错**），再拍真图。viewport-only（1280×720，device_scale_factor=1），不是整页。
2. **绿框高亮** `run.py:489-499`：若 `action["element_id"]` 非空，用 `page.query_selector("[data-label-id='<id>']")` 拿 bounding_box，`cv2.rectangle` + `cv2.circle` 画绿色 (0,255,0) 框和中心点。`data-label-id` 由 `html_tools/scripts/label.js` 在 `modify_page()` 时**注入到活 DOM**（顺序序号，非稳定 id，每次观测重排），下一次观测开头由 `remove_id_script` 清掉 → 所以截图时属性还在，框能画上。
3. **`result_dir/render_{task_id}.html`**：`RenderHelper`（browser_env/helper_functions.py:161）逐步追加 URL + 文本观测 + `observation["image"]` 的 base64 内嵌图 + 动作历史。注意这张图来自观测处理器**另拍的**一张 `page.screenshot()`（processors.py:1153 `png_bytes_to_numpy`），与第 1 条不是同一张。`get_unfinished()` 就是靠 glob `*.html` 判断任务的。

5. **`Eval/debug_info/`**（相对 cwd，每步覆盖）：`screenshot_raw.png`（注入 data-bbox 后）、`marked.png`（label_marker.js 画完标记后）、`raw.html`、`parsed.html`、`all_element.json`，来自 `html_tools/fetch.py:31,48,66`。

## 登录链路（第六轮，用户问"是不是没登录"）
结论：**登录有做，而且是逐任务由 run.py 现场做的**，但存在静默失败风险。
- `run.py:398-419`：每个任务若 `_c["storage_state"]` 非空 → `subprocess.run(["python","browser_env/auto_login.py","--auth_folder",<tempfile.mkdtemp()>,"--site_list",*comb])` → 再把 `_c["storage_state"]` 指向临时目录的新 cookie → `assert os.path.exists(...)`。
- **`.auth/shopping_admin_state.json` 的内容从不被读取**，只用 `os.path.basename` 推导站点组合（`get_site_comb_from_filepath` → "shopping_admin_state.json" → `['shopping_admin']`）。`get_unfinished()` 用 glob `*.html` 判断，与登录无关。
- **`require_login` 字段 Eval 里没有任何逻辑读它**（只有 `scripts/generate_config_files.py:136` 写入和 tests 里出现）。真正的开关是 `storage_state` 的真值。
- 35 个 shopping_admin 任务全部 `storage_state='./.auth/shopping_admin_state.json'` + `require_login=True`。
- **影响面**：eval_types 分布 = string_match 19 / program_html 11 / url_match+program_html 3 / url_match 2。即 **14/35 (40%) 依赖已登录上下文** —— `program_html` 评测器会 `page.goto(target_url)` 后取 `page.content()` 或 evaluate JS（evaluators.py:365-396），没登录会被 Magento 重定向到 `/admin` 登录页 → locator 查不到元素 → 静默 0 分。`url_match` 读 `page.url` 且 `clean_url` 统一把 localhost 换成 127.0.0.1（evaluators.py:319-325）。
- **两个隐患**：
  1. `run.py:405` 硬编码 `"python"`（**不是 `sys.executable`**），且 `subprocess.run` 无 `check=True`。所以如果 `PYTHON` 指向绝对路径的 venv 而没 activate，run.py 会用那个解释器跑、登录子进程却用裸 `python` → 失败表现为 `assert os.path.exists` 抛错（走 except 写进 `result_dir/error.txt`），任务跳过不计分。
  2. `auto_login.py` 走 `--site_list` 分支时**跳过 `is_expired` 校验**（只有不带参数走 `main()` 才校验），所以"跑完不报错"≠"真登录上了"。
- **新增 `Eval/scripts/check_login.py`**：加载 cookie 后实际打开 `<SHOPPING_ADMIN>/dashboard`，检查最终 URL 含 "dashboard" 且页面含关键字 "Dashboard"，退出码 0/1，失败时打印排查方向。
- **`evaluate_shopping_admin.sh` 加了两处防护**：① 前置检查里比对 `PYTHON` 与 `command -v python` 是否同一环境，不一致直接 die；② REFRESH_AUTH 之后跑 check_login.py，无效则 die（可用 `REFRESH_AUTH=0` 跳过）。
- 登录动作的细节：`auto_login.renew_comb()` **另开一个 headless Chromium**（`HEADLESS=True`）走登录表单 —— `page.goto(SHOPPING_ADMIN)` → `get_by_placeholder("user name")` 填 `ACCOUNTS["shopping_admin"]["username"]`（= admin）→ `get_by_placeholder("password")` 填 `admin1234`（env_config.py:95）→ 点 `Sign in` → `context.storage_state()` 存盘 → 关掉这个浏览器。真正跑任务的浏览器（envs.py:184-189 `new_context(storage_state=...)`）**自己从不输密码**，只是加载 cookie。
- 所以登录是**每任务一次**（35 个任务 = 35 次登录 + 我脚本里的 1 次预热），每次都要起一个完整浏览器，是纯开销。
- 这套登录能成立的前提是 `start_shopping_admin.sh` 里打的 patch：`admin/security/password_is_forced 0` + `password_lifetime 0`（`05_docker_patch_containers.sh`）。否则 Magento 会强制改密码/会话过期，自动登录直接失效。
